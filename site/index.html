From repository to guide

The agent writes.
xpl checks.

xpl checks where each code link points and that the code has not changed. The author still has to get the text right.

  1. Index the repository

    xpl finds files, symbols and references. Each reference is labelled precise (checked by a language tool) or heuristic (matched by name).

  2. The agent writes a patch

    You ask a question. The agent writes diagrams, short notes and links to the code, as data.

  3. xpl checks the code links

    Each code link must point at real code that has not changed. A missing or changed link stops the export. A person still reviews the text.

  4. Read it. Share it.

    Read the diagrams beside the code, follow the tour step by step, or export one HTML file with the code inside.

Try it on your repository

Start with a question.

Install from npm with Node 22.12 or newer. The source is available on GitHub.

xpl reads TypeScript, JavaScript, Python, Go and Java, and Rust (declarations, some calls, imports within the package), Ruby and PHP in part: languages and precision.

Read Getting started

Install xpl and its skill for Claude Code:

npm install --global @krimvp/xpl
xpl skill install

In Claude Code, in your repository, ask a question:

/code-explainer explain How does a failed job get retried? Audience: maintainers.

Other agents (Codex, Pi, Factory Droid, Devin) and the install from a source checkout are in the install options. /code-explainer is a chat command for your agent, not a shell command.

No agent? Draft a guide with the CLI alone, then write its text yourself:

xpl index
xpl outline    # find the id of the function where the answer starts
xpl start my-guide --question "How does a failed job get retried?" \
  --entry <id> --audience maintainers
xpl view my-guide

The skill indexes your project, writes the guide and checks it before it opens.
